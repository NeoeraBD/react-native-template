# Workspace Coding Instructions (.instructions.md)

This file contains the core project rules, architecture patterns, and optimization guidelines for all developers and Generative AI Coding Agents (such as Claude, Gemini, ChatGPT, and Cursor).

---

## 🦄 1. The Ponytail Rule (Lazy Senior Developer Principle)

- **Do Not Over-Engineer**: Always pull the simplest, most direct lever that solves the problem. Do not write new code or add dependencies unless absolutely necessary.
- **Check and Reuse Existing Utilities**: Before implementing any new helper (e.g. download managers, encryption engines, local caching systems), inspect `packages/core/src/utils/` (such as `downloader`, `crypto`, `offlineCache`, `documentViewer`, `secureStorage`) and use them first.
- **Do Not Compromise Quality**: The Ponytail Rule is **not** an excuse to cut corners on security, input validation, type checking, error handling, or null safety. Keep your code footprint as small and simple as possible while maintaining maximum safety.

---

## 🚀 2. Prompt & Token Efficiency (For AI Agents)

- **Keep Responses Concise**: Focus on providing raw code modifications and short, precise rationales. Skip polite filler, summaries, and conversational intros/outros.
- **Targeted Code Output**: Do not rewrite entire files. Output modifications as clean, unified git diffs or small, specific replacement functions.
- **Reference Existing Code**: Reference existing file symbols and types rather than copying definitions into the prompt response.

---

## 🛡️ 3. TypeScript & Strict Null Safety

- **Mandatory Optional Chaining**: Always use optional chaining (`?.`) and nullish coalescing (`??`) when accessing API payloads, state stores, or nested structures. Never trust backend formats implicitly.
- **Defensive API Mapping**: Validate all nested elements and provide fallback defaults when parsing API responses.
- **Safe Component Styles**: Custom component style overrides passed to components must always utilize `StyleProp<ViewStyle>` or `StyleProp<TextStyle>` to avoid react-native styling mismatches.
- **Validation**: Always run type checking using `yarn tsc -p tsconfig.json --noEmit` to verify code changes.

---

## 🏛️ 4. MVVM & Repository Pattern

- **Views**: Pure React functional components. No business logic or state mutations.
- **ViewModels**: Custom hooks containing component states, form validation, and calls to repositories. No direct Axios or MMKV storage calls.
- **Repositories**: Single source of truth. Manages caching (`offlineCache`) and API fetches (`apiRequest`).
