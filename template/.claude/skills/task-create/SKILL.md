# task-create — Project & Figma-Grounded OpenSpec Task Generator

Transform high-level feature requests and design canvases into an actionable, production-ready master task list and implementation prompts:
**User Goal / Task -> Full Project Review -> OpenSpec Assets & Figma Review -> Goal Sub-Task Breakdown -> Save to OpenSpec Context File**

Tasks generated by this skill strictly adhere to the React Native architecture and are 100% compatible with the **`openspec-task-cycle`** execution pipeline (supporting single-worker or multi-agent parallel execution).

---

## Complete Workflow Overview

```
                        User Gives Task / Goal
                                  │
                                  ▼
                   [Phase 1: Deep Project Review]
         Architecture (AGENTS.md, project.md, design-system.md)
         + Codebase Scan (packages/core, packages/ui, src/screens)
                                  │
                                  ▼
              [Phase 2: OpenSpec Assets & Figma Review]
         openspec/assets/manifest.json, screens/, components/,
         Figma Canvas/Node IDs, Design System Tokens
                                  │
                                  ▼
             [Phase 3: OpenSpec Context Status Review]
         Inspect openspec/context/*.md, identify completed tasks,
         module sequence, and determine target context file
                                  │
                                  ▼
                [Phase 4: Goal & Sub-Task Breakdown]
         Decompose into atomic tasks: Checklist + High-Fidelity Prompts
         (Target files, layout, state, styling, reuse, tests)
                                  │
                                  ▼
             [Phase 5: Write to OpenSpec Context File]
         Save to openspec/context/<file>.md + Update manifest.json
                                  │
                                  ▼
              [Ready for Execution: openspec-task-cycle]
```

## Detailed Step-by-Step Instructions

### Step 1: Ingest & Clarify User Goal

1. **Parse User Input**:

   - Extract the core task/feature (e.g., "Build notification center", "Add supplier purchase orders & returns", "Implement customer loyalty screen").
   - Extract any Figma URLs, node IDs (e.g., `4820:15391`), screenshots, or design assets provided by the user.

2. **Clarification Gate**:
   - If the task is ambiguous or missing critical scope parameters, ask targeted questions:
     - Target user personas (Cashier, Store Owner, Customer).
     - Navigation location (Bottom tab, stack modal, drawer).
     - Specific Figma canvas or frame IDs (if external design exists).
   - If sufficient context is provided, proceed immediately without unnecessary back-and-forth.

---

### Step 2: Full Project & Architecture Review

Before generating any tasks, review the codebase architecture and existing implementation to ensure sub-tasks fit seamlessly into the existing structure:

1. **Review Architecture Invariants**:

   - Consult `.agents/AGENTS.md`, `openspec/project.md`, and `openspec/design-system.md`.
   - **Enforce Non-Negotiables**:
     - **TypeScript Only**: All code must be `.ts` or `.tsx` (strict mode). No loose JavaScript.
     - **Layout Wrapper**: Every screen view must be wrapped in `ContainerNew` from `@components/Container` (or `@app/ui`) for safe area handling, keyboard avoidance, and loading overlays.
     - **Page Headers**: Always use `CustomHeader` or `HeaderOrder` from `@app/ui` (never ad-hoc header layouts).
     - **Styling**: Companion `<ScreenName>.style.ts` file using `StyleSheet.create` and `getStyles(colors)` with `useAppTheme()`. Zero raw hex colors (e.g., `#111E2F`), zero raw CSS color strings (`red`, `white`), zero inline style objects (`style={{ ... }}`).
     - **State Management**: MobX 6 + `mobx-react-lite` `observer`. Any screen or custom component reading store properties must be wrapped in `observer` from `mobx-react-lite` (never `mobx-react`). Store mutations must only happen through defined store actions.
     - **MVVM Architecture**:
       - **View** (`src/screens/<screen>/<Screen>Screen.tsx`): Pure presentational structure and user event dispatching.
       - **ViewModel** (`src/screens/<screen>/use<ScreenName>ViewModel.ts`): UI logic, form handling (`react-hook-form`), store bindings.
       - **Repository** (`packages/core/src/repository/`): Single source of truth with TTL caching (`offlineCache.getOrFetch`).
       - **Network** (`packages/core/src/network/HttpRequest.ts`): Strictly Supabase REST through shared `httpRequest` and `ApiEndPoints.ts` (never call raw `axios` or create new Supabase clients).
     - **Ponytail Rule (Lazy Senior Dev)**: YAGNI. Inspect and reuse existing components from `@app/ui` and utilities from `@app/core` before proposing new code. Shortest working diff wins.

2. **Scan Existing Codebase Assets**:
   - Check existing screens in `src/screens/` and navigation routes in `src/navigation/`.
   - Check existing reusable UI components in `packages/ui/src/components/` (e.g., `CustomButton`, `CustomInput`, `CustomChip`, `ProductCard`, `TopProducts`, `QtyStepper`, `CheckoutBar`, `GlassView`, `SegmentedTabs`, `FinancialInfoCard`, `CustomFlatList`, `CustomToast`).
   - Check existing stores in `packages/core/src/store/` and repositories in `packages/core/src/repository/`.

---

### Step 3: OpenSpec Assets & Figma Design Review

1. **Inspect Asset Manifest**:

   - Read `openspec/assets/manifest.json`.
   - Check:
     - `figmaUrl`: Base Figma project design URL.
     - `canvas`: Active canvas ID and name (e.g., Canvas `X2`, node `4820:10966`).
     - `screens`: Existing mapped screen node IDs and image file paths (`openspec/assets/screens/<name>.png`).
     - `components`: Existing mapped component node IDs and image file paths (`openspec/assets/components/<name>.png`).

2. **Review Design Assets**:

   - Inspect existing screen snapshots in `openspec/assets/screens/` to understand visual language, spacing, card layouts, and button placements.
   - If user provided Figma node IDs or new screens:
     - Match each screen to a corresponding Figma node ID and target image path: `openspec/assets/screens/<screen-name>.png`.
     - Prepare entry to append to `openspec/assets/manifest.json`.

3. **Align Design System Tokens**:
   - Reference `openspec/design-system.md` for:
     - **Color Tokens**: `colors.primary` (`#00DD88`), `colors.background`, `colors.surface`, `colors.onSurface`, `colors.outline`, `colors.error`, etc.
     - **Typography Scale**: `HeadlineLarge` (28px bold), `TitleMedium` (18px semibold), `BodyMedium` (14px regular), `LabelSmall` (11px).
     - **Component Spacing & Elevation**: 8px grid, card border radiuses (12px - 16px), glassmorphism presets.

---

### Step 4: OpenSpec Context Status & Sequencing

1. **Inspect Context Directory**:

   - Check `openspec/context/` for existing context files:
     - Default master file: `openspec/context/screens-uiux-tasks-and-prompts.md`.
   - Scan current tasks:
     - Check completed tasks (`- [x]`) and in-progress tasks (`- [/]`).
     - Identify current highest Module number (e.g., Module 5: Supplier & Vendor Ledger Module).
     - Next module will be `Module 6`, or if creating a new epic, define a dedicated module sequence.

2. **Select Target Context File**:
   - **Option A (Append to Master)**: If the task is a continuation of the main screen rollout, append as a new Module (e.g., `### Module 6: ...`) in `openspec/context/screens-uiux-tasks-and-prompts.md`.
   - **Option B (New Context File)**: If the task is a major standalone epic or new subsystem, create a new context file `openspec/context/<feature-name>-tasks-and-prompts.md`.

---

### Step 5: Goal Breakdown & Sub-Task Generation

Decompose the user's goal into atomic, sequential sub-tasks. Each sub-task must follow the exact structure required by `openspec-task-cycle`.

#### 1. Master Task Checklist Entry Format

Every sub-task in the checklist section must strictly follow this syntax:

```markdown
### Module <N>: <Module Title>

- [ ] **Task <N>.<M>: <Task Title>**
  - Figma: `<Node ID or N/A>` | Asset: `openspec/assets/screens/<asset-name>.png`
  - Target: `<target-screen-file>` & `<target-style-file>`
```

#### 2. High-Fidelity Implementation Prompt Entry Format

Every sub-task must have an accompanying detailed prompt section:

````markdown
---

### Screen <X> / Task <N>.<M>: <Task Title>

- **Figma Node:** `<Node ID>` (<width> x <height>)
- **Asset:** `openspec/assets/screens/<asset-name>.png`
- **Target Files:**
  - Screen: `src/screens/<module>/<ScreenName>Screen.tsx`
  - Companion Style: `src/screens/<module>/<ScreenName>Screen.style.ts`
  - ViewModel: `src/screens/<module>/use<ScreenName>ViewModel.ts`
  - Unit Test: `src/screens/<module>/<ScreenName>Screen.test.tsx`

#### Prompt:

```markdown
Implement the <Task Title> matching Figma node <Node ID>.

1. Layout & Composition:

   - Wrap in ContainerNew from @components/Container.
   - Header: CustomHeader (or HeaderOrder) from @app/ui with back button, center title, and right action buttons.
   - Top Section: [Describe top cards / search bars / filter chips].
   - Main Body: [Describe list / form / cards / data display].
   - Bottom Dock: [Describe bottom CTA / floating dock / action buttons].

2. State & MobX Integration:

   - Wrap component in observer from mobx-react-lite.
   - Connect to <StoreName> (e.g., OrderStore, KhataStore, InventoryStore, etc.).
   - ViewModel: use<ScreenName>ViewModel orchestrates UI events, validation, and repository queries.
   - Navigation: [Describe navigation triggers and route parameters].

3. Styling Rules:

   - Companion file <ScreenName>Screen.style.ts using StyleSheet.create and getStyles(colors).
   - Consume colors from useAppTheme(). Zero hardcoded hex codes, zero inline styles.
   - Match spacing, borders, and typography from openspec/design-system.md.

4. Component Checklist & Reuse:

   - Reuse: [List components from @app/ui and @app/core].
   - Do NOT reinvent existing primitives (e.g., use CustomButton, CustomSearchbar, CustomChip, CustomFlatList).

5. Scoped Verification Suite:
   - Typecheck: `yarn tsc -p _tsconfig.json --noEmit`
   - Linter: `npx eslint <target-files>`
   - Unit Test: `yarn test <test-file>`
```
````

````
### Step 6: Write to OpenSpec Context File & Update Manifest

1. **Write Context File**:
   - Save or append the generated content to the designated file in `openspec/context/`.
   - Ensure the markdown is well-formatted, contains zero syntax errors, and maintains standard `- [ ] **Task X.Y: ...**` markers.

2. **Update Manifest (if new screens/assets added)**:
   - If new Figma screens were defined, update `openspec/assets/manifest.json`:
     ```json
     {
       "id": "<figma-node-id>",
       "name": "<screen-slug>",
       "file": "openspec/assets/screens/<screen-slug>.png",
       "dimensions": {
         "width": 390,
         "height": 812
       }
     }
     ```

3. **Report Outcome & Next Steps**:
   - Summarize the new tasks created:
     - Context file path.
     - Module name & task IDs created.
     - Target files for each task.
     - Figma / Asset mappings.
   - Provide the exact invocation command to begin implementation:
     - For single worker: `Run openspec-task-cycle`
     - For parallel workers: Launch worker subagents with roles `Worker-A`, `Worker-B` using `openspec-task-cycle`.
````
